# Quizkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Quizkit v1: an offline Expo/React Native app that imports LLM-generated quiz JSON, organizes quizzes in folders, and runs them in Practice or Exam mode with LaTeX, results, review, and redo-wrong.

**Architecture:** Pure TypeScript domain and engine layers (import parsing, math segmenting, session logic) are built test-first and know nothing about React or Expo. SQLite sits behind small repository interfaces (tested against `better-sqlite3`, run in production on `expo-sqlite`). Zustand stores wire repos and engine to Expo Router screens. All math rendering goes through one `MathText` component.

**Tech Stack:** Expo (current stable SDK) + TypeScript strict, Expo Router, Zustand, Zod, expo-sqlite, katex, react-native-webview, expo-document-picker, expo-clipboard, expo-file-system, expo-localization, expo-crypto, Jest (`jest-expo`), `better-sqlite3` (dev only), `@testing-library/react-native`.

**Spec:** `docs/superpowers/specs/2026-10-27-quizkit-design.md` (section numbers below, "§", refer to it). Read it before starting; this plan only records decisions the spec does not already pin.

## Global Constraints

- TypeScript `strict: true`. Expo Router for navigation. No network calls anywhere; no analytics.
- Import JSON: `schemaVersion` must be `1`; `title` 1–120 chars after trim; `questions` 1–5000; input size cap about 10 MB; `options` 2–6 non-empty strings; `answer` is a letter `A`–`F`, case-insensitive, within the option count; unknown fields are stripped, not errors; images are stripped with a warning, not failure.
- Import is strict: any structural error rejects the whole import. Show at most about 10 problems plus a "+N more" count. Warnings (odd `$`, unparseable math, duplicate options, duplicate questions, images, repaired backslashes) never block.
- Skipped (unanswered) questions count as wrong. Practice mode locks the first pick; Exam mode allows changing answers until submit.
- Exam stopwatch counts foreground time only (pauses in background). Stopwatch, not countdown.
- Default shuffle: question order off for a single quiz and on for a folder run; option order off always by default.
- Every user-visible string comes from `src/i18n/en.json` / `tr.json` (Turkish and English, device language if tr/en else en). No hard-coded UI strings.
- Plain text only (no Markdown/HTML). Correct/wrong must not be signaled by color alone (✓/✗ icons).
- Verified on the owner's iPhone (Expo Go or dev build). Android is checked on an emulator only, best effort.
- The folder is not yet a git repository: Task 1 runs `git init`. Add `.superpowers/` to `.gitignore`.
- Commit messages end with: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

Inputs the spec implies but its own tests would not catch, most likely first. Each line is pinned by a test in the named task.

1. **LLM reply with chatter around the JSON** ("Here is your quiz:" + fenced JSON + "Let me know if…", or two JSON objects). Expect: use the first top-level object that has a `questions` key; otherwise a syntax error. (Tasks 4, 6)
2. **Redo-wrong when nothing was wrong, and exam submit with zero answers.** Expect: no empty session is ever created (button hidden); submitting with nothing answered warns with the total count and yields score 0/N. (Tasks 8, 14)
3. **Double-tapping Next or an option.** Expect: no skipped question and no double-counted answer (navigation uses absolute indexes). (Tasks 8, 9, 13)
4. **A very long option or explanation (10,000 chars) and a string with thousands of `$`.** Expect: segmenting is linear time, rendering scrolls and does not freeze. (Tasks 5, 13)
5. **Turkish names: `İ`/`ı` ordering of folders and quizzes**, plus emoji in titles. Expect: Turkish-locale alphabetical order, nothing truncated mid-emoji. (Task 11)

### Task 4: normalizeInput and backslash repair

**Files:** Create `src/domain/normalizeInput.ts`; Test `src/domain/__tests__/normalizeInput.test.ts`.

**Interfaces:**
- Produces:
  - `extractJson(raw: string): string | null` — strips BOM and ```` ```json ```` fences, finds the first balanced top-level `{...}` that contains a `"questions"` key (string-literal aware), else `null`.
  - `repairBackslashes(json: string): { json: string; fixed: number }` — inside string literals only: a `\` not followed by one of `" \ / b f n r t` becomes `\\`; `\u` not followed by four hex digits also becomes `\\u`; smart quotes (`“ ” ‘ ’`) outside string literals become `"`/`'`.
  - `restoreLatexEscapes(value: unknown): { value: unknown; fixed: number }` — walks parsed JSON strings. U+000C → `\f`, U+0008 → `\b` always. Tab/newline/carriage-return characters are restored to `\t`/`\n`/`\r` only when inside a `$…$` span and followed by a known LaTeX command name (a list including `times`, `theta`, `tau`, `text`, `neq`, `nu`, `ne`, `rho`, `right`, `rightarrow`, `beta`, `bar`, `frac`).

- [ ] **Step 1:** Write failing tests:
  - `extractJson` on `Here you go:\n```json\n{"questions":[]}\n```\nEnjoy` returns `{"questions":[]}`; with two objects where only the second has `questions`, returns the second (Review Focus 1); with no object returns `null`; with a leading BOM still works.
  - `repairBackslashes('{"a":"\\alpha"}')` gives `fixed: 1` and `JSON.parse(result.json).a === '\\alpha'`; `'\\(x\\)'` repaired; valid `\n` untouched (`fixed: 0`); smart quotes around keys outside strings become straight quotes but a `“` inside a string value is preserved.
  - `restoreLatexEscapes(JSON.parse('{"q":"$\\frac{1}{2}$"}'))` returns `$\frac{1}{2}$` (form feed restored, `fixed: 1`); `'$a \\times b$'` (tab char before `imes`) restored; a real newline outside math (`"line1\nline2"`) is untouched; `'$\\neq$'` restored from newline; `'$\\beta$'` restored from backspace.

### Task 5: Math segmenter

**Files:** Create `src/domain/mathSegments.ts`; Test `src/domain/__tests__/mathSegments.test.ts`.

**Interfaces:**
- Consumes: `Segment` (Task 2).
- Produces: `segment(text: string): { segments: Segment[]; unmatchedDollars: number }`; `hasMath(segments: Segment[]): boolean`.

Performance (Review Focus 4): a 200,000-char string of repeated `'$a '` segments returns in under 200 ms; a 10,000-char single-line text segment returns one segment.
