# Quizkit Web (PWA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Quizkit as an installable, offline-capable web app (PWA) hosted on GitHub Pages, so the owner can use it on iPhone via "Add to Home Screen" with no Apple ID, no 7-day re-signing and no cable.

**Architecture:** Same Expo codebase, exported with `expo export -p web` (single-page output). Platform differences are isolated behind Metro platform extensions (`foo.ts` native, `foo.web.ts` web) so native keeps working unchanged. SQLite on web is `sql.js` (WASM) held in memory and snapshotted to IndexedDB after every write, behind the existing `SqlDb` interface, so repositories, migrations and SQL stay identical. A generated service worker precaches the whole build. Deployed by a GitHub Actions workflow to Pages under `/quizkit/`.

**Tech Stack:** Expo SDK 58 web (react-native-web, expo-router), `sql.js`, IndexedDB, Service Worker, Web Locks API, GitHub Pages; tests: Jest (`jest-expo`) + `fake-indexeddb`.

**Spec:** Original app design `docs/superpowers/specs/2026-10-27-quizkit-design.md` (behavior is unchanged; this plan only adds a web target). Decisions made for the web target, from the conversation of 2026-11-15:
- Web is the owner's daily-use target; native code stays and keeps passing tests.
- Hosting: GitHub Pages, free, HTTPS, base path `/quizkit/`.
- `expo-sqlite` web is NOT used (needs COOP/COEP headers that Pages cannot send).
- A backup/restore file is provided because browser storage is not guaranteed durable.

## Global Constraints

- Native behavior and all 307 existing tests must keep passing after every task (`npm test`, `npm run typecheck`).
- No network requests at runtime after first load: everything (JS, WASM, KaTeX fonts, icons) is precached. No analytics, no remote fonts.
- Never edit `ios/` or `android/`. Web config goes in `app.json` and `src/app/+html.tsx`.
- Web files use the `.web.ts(x)` suffix; native files must not import web-only APIs and vice versa. `expo-sqlite`, `react-native-webview`, `expo-symbols` must not be reachable from the web bundle.
- Asset URLs must work under the `/quizkit/` base path (`experiments.baseUrl`).
- Turkish and English strings for every new user-visible text (`src/i18n/en.json`, `tr.json`); a test enforces key parity already.
- Commit after every task; end messages with the Co-Authored-By line the session specifies.

## Review Focus

1. Two windows open at once (Safari tab + home-screen app) each snapshotting the DB → last writer silently erases the other's data. Expected: the second window refuses to open the DB and says why. (Task 1)
2. IndexedDB unavailable or full (private mode, quota) → writes must fail loudly, never appear saved. (Task 1)
3. After a deploy, a stale service worker keeps serving the old build forever, or serves an old `index.html` with new hashed JS missing. Expected: new build is picked up on the next launch, never a mixed state. (Task 7)
4. Deep-link/refresh on a route (e.g. `/quizkit/quiz/abc`) on GitHub Pages returns 404. Expected: app shell loads. (Task 6, 8)
5. A corrupt or hostile backup file must not wipe existing data: restore validates first and replaces inside one transaction. (Task 5)

### Task 1: Web SQLite adapter (the risky part, done first)

**Files:**
- Create: `src/db/webSnapshotStore.ts`, `src/db/webSqlDb.ts`
- Test: `src/db/__tests__/webSqlDb.test.ts`
- Modify: `package.json` (add `sql.js` dependency, `fake-indexeddb` devDependency, via `npx expo install` / `npm i -D`)

**Interfaces:**
- Consumes: `SqlDb` (`src/db/sqlDb.ts`), `migrate`, `openMigrated`.
- Produces:
  ```ts
  export interface SnapshotStore { load(): Promise<Uint8Array | null>; save(bytes: Uint8Array): Promise<void>; delete(): Promise<void> }
  export function createIdbSnapshotStore(dbName: string): SnapshotStore;
  export class DatabaseLockedError extends Error {}
  export async function openWebDb(opts: { name: string; snapshots: SnapshotStore; locateWasm: (file: string) => string; lock?: { acquire(name: string): Promise<boolean> } }): Promise<SqlDb>;
  ```

- [ ] **Step 1: Write failing tests** in `webSqlDb.test.ts` (use `fake-indexeddb/auto`, real `sql.js` from node_modules with `locateWasm` pointing at its `dist` file):
  - `persists across reopen`: open, `run('CREATE TABLE t(x)')`, `run('INSERT INTO t VALUES (?)',[1])`, `close()`, open again with same store → `getAll('SELECT x FROM t')` equals `[{x:1}]`.
  - `transaction rolls back on throw`: insert inside `transaction` then throw → table empty and snapshot unchanged.
  - `migrations run`: `openMigrated(() => openWebDb(...), migrate)` then `getFirst('SELECT COUNT(*) AS n FROM folders')` → `{n:0}`; foreign keys enforced (inserting a quiz row with a missing folder_id fails).
  - `save failure surfaces`: store whose `save` rejects → `run` rejects (not swallowed).
  - `second opener is refused`: `lock.acquire` returns `false` → `openWebDb` rejects with `DatabaseLockedError`.
  - `concurrent transactions serialize`: two `transaction`s started together never interleave their statements.
- [ ] **Step 2: Run** `npx jest src/db/__tests__/webSqlDb.test.ts` → FAIL (module missing).
- [ ] **Step 3: Implement** `webSnapshotStore.ts` (one object store `snapshots`, key = `dbName`) and `webSqlDb.ts`. Approach: `initSqlJs({locateFile})`, `new SQL.Database(bytes ?? undefined)`, `PRAGMA foreign_keys = ON`; `getAll/getFirst` via prepared statements; `transaction` uses a promise-chain mutex + `BEGIN/COMMIT/ROLLBACK`; after every write outside a transaction and after every `COMMIT`, `await save(db.export())` through a coalescing queue (one in flight + one pending, rejections propagate to the callers waiting on that save). Default `lock` uses `navigator.locks.request(name, {ifAvailable: true}, …)` held until `close()` or page end; when `navigator.locks` is missing, treat as acquired.
- [ ] **Step 4: Run** the test file → PASS; run `npm test` → all green.
- [ ] **Step 5: Commit** `feat(web): sql.js database adapter with IndexedDB snapshots`.

### Task 7: Offline service worker

**Files:**
- Create: `scripts/build-sw.ts`, `src/web/registerServiceWorker.ts`
- Modify: `package.json` (`"build:web": "expo export -p web && npm run build:sw"`, `"build:sw": "tsx scripts/build-sw.ts"`), `src/app/_layout.tsx` (register on web in production only)
- Test: `scripts/__tests__/build-sw.test.ts`

**Interfaces:**
- `buildSw(files: string[], buildId: string): string` returns the SW source. Behavior it must encode: cache name `quizkit-<buildId>`; on `install` precache every file (including `index.html`) then `skipWaiting()`; on `activate` delete other `quizkit-*` caches and `clients.claim()`; `fetch`: navigation requests → cached `index.html` (this also fixes refresh on deep links), everything else cache-first, never caches non-GET or cross-origin.
- `buildId` = hash of the sorted file names + their sizes.
- `registerServiceWorker(): void` registers `${baseUrl}sw.js` after `load`; on `controllerchange` does nothing during a session (new build applies on next launch; avoids mixed old/new state).

- [ ] **Step 1: Tests** (`build-sw.test.ts`): generated source contains every given file path and the build id; different file lists give different ids; `index.html` is in the list; evaluating the SW source in a stubbed `self` with `caches`/`fetch` fakes: navigation to `/quizkit/quiz/x` is answered from cached `index.html`; a POST is not intercepted; activation deletes an older `quizkit-old` cache.

- [ ] **Step 4: Run** `npm test` → PASS; `npm run build:web` → `dist/sw.js` lists the JS bundle, wasm, fonts and icons.
- [ ] **Step 5: Offline check in a browser:** serve `dist`, load once, stop the server, reload → app works; rebuild with a changed string, serve, reload twice → new version appears on the second load.
